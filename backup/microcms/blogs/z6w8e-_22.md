# はじめに

[前回の記事](https://tokiolab.dev/blog/75po7aaqvrdd/)では、JavaScriptを例にスタックとヒープの仕組みや役割を整理しました。

今回は、

- 値渡しと参照渡し
- オブジェクトや配列のシャローコピーとディープコピー

といった実際のコーディングでよく目にする記述を、スタックとヒープに着目しながらメモリの挙動がどう違うかを整理します。

# 値渡しと参照渡し

```javascript
/*
 * 値渡し
 */
let a = 10;
let b = a; // 10という値を代入
b = 20;

console.log(a); // 10 (aは影響を受けない)
console.log(b); // 20

/*
 * 参照渡し
 */
let obj1 = { val: 10 };
let obj2 = obj1; // オブジェクトのヒープアドレスを代入
obj2.val = 20;

console.log(obj1.val); // 20 (obj1も影響を受ける)
console.log(obj2.val); // 20
```

#### メモリの動き

- 値渡し
  1.  `a = 10`の時、スタック上に直接`10`という値が保存される。
  2.  `b=a`とすると、スタック上に新しい領域が作られ`10`がコピーされる。それぞれ独立している。
- 参照渡し
  1.  `obj1 = { val: 10 }`の時、ヒープ上にオブジェクト`{ val: 10 }`が作られる。スタック上の`obj1`にはそのヒープの住所(メモリアドレス `0x001`)が保存される。
  2.  `obj2 = obj1`とすると、スタック上で`0x001`というメモリアドレスがコピーされる。結果として同じメモリを見ているため、一方の変更がもう一方に影響する。

値渡しは、値のコピー(複製)がそのままできます。

しかし、オブジェクトや配列のコピーをしようと単に別の変数に代入するだけでは値のコピーはできません。

ではどのようにすればコピーができるでしょうか？

⚠️ここからの説明はオブジェクトに限定しますが、配列等など参照型の値は全て当てはまります。

## フラットなオブジェクトのコピー

以下のように、スプレッド構文や`Object.assign()`を使うとコピーできます。

```javascript
let obj1 = { val: 10 };
// スプレッド構文によるコピー
let obj2 = { ...obj1 };

// Object.assign()によるコピーでも同様の挙動
// let obj2 = Object.assign({}, obj1);

obj2.val = 20;

console.log(obj1.val); // 10 (obj1は影響を受けない)
console.log(obj2.val); // 20
```

この時のメモリの動きは以下です。

#### メモリの動き

1.  `{ val: 10 }`がヒープに保存され、そのアドレス(`0x001`)がスタック上の`obj1`に保存される
2.  `{ ...obj1 }`もしくは`Object.assign({}, obj1)`により、新たなヒープ領域にオブジェクトが保存され、そのアドレス(`0x002`)が`obj2`に保存される

以上により、`{ val: 10 }`は別々のヒープ領域に保存されることになります。

しかし、ここで注意事項があります。

オブジェクトがオブジェクトを持つようなネスト構造のオブジェクトは挙動が変わります。

例えば、オブジェクトに`address`というプロパティがあり、そこにオブジェクトがある構造を考えてみます。

## ネスト構造のオブジェクトはどのように保存されるか

```
const original = { name: "Alice", address: { city: "Tokyo" } };
```

まず、上記のネストされたオブジェクトが保存される時のメモリの挙動を見てみます。

#### メモリの動き

1.  **内側のオブジェクトがヒープに作られる** : `{ city: "Tokyo" }`が`0x001`というアドレスに作られる
2.  `外側のオブジェクトがヒープに作られる` : `{ name: "Alice", address: 0x001 };`が`0x002`に作られる
    - `name`プロパティは`Alice`という値が書かれるが、`address`の値はオブジェクトなので、そのアドレスが書かれる
3.  `最後にスタック変数が積まれる` : `original`という変数がスタックに積まれ、`0x002`が保存される

これを踏まえて、オブジェクトのコピーの方法を見ていきます。

# シャローコピー

**シャローコピー**とは、1階層だけ新しいオブジェクトを作成するコピーです。

以下のように、スプレッド構文や`Object .assign()`を使ってコピーをするとシャローコピーになります。

```javascript
const original = { name: 'Alice', address: { city: 'Tokyo' } };

// シャローコピー（スプレッド構文を使った例)
const shallow = { ...original };

// シャローコピー2(Object.assignを使った例)
// const copy = Object.assign({}, original);

// 1階層目（プリミティブな値）の変更
shallow.name = 'Bob';
console.log(original.name); // "Alice" （ここは独立しているので元のデータは変わらない）

// 2階層目（ネストされたオブジェクト）の変更
shallow.address.city = 'Osaka';
console.log(original.address.city); // "Osaka" （元のデータも変わってしまう）
```

上記は以下の動きになります。

#### メモリの動き

1.  `original = { name: "Alice", address: { city: "Tokyo" } };`の時、以下の挙動になる。
    1.  `{ city: "Tokyo" }` がヒープに保存され、そのアドレス(`0x001`)が`addressに保存される。`
    2.  `{ name: "Alice", address: 0x001 };`がヒープに保存され、スタック上の`original`にそのアドレス`(0x002)`が保存される。
2.  `shallow = { ...original };`とすると、新しいヒープ領域(`0x003`)が確保され、1階層目の`{ name: "Alice", address: 0x001 };`が保存される

つまり、1階層目のオブジェクトは新しいヒープに作成されるがネストされた2階層目のオブジェクトは元の参照のままです。

これがシャローコピーの挙動です。

# ディープコピー

一方、ネストされたオブジェクトも含めて、すべての階層で新しく完全に独立したオブジェクトを作成するコピーを**ディープコピー**と呼びます。

JavaScriptでは、最近の標準機能である`structuredClone()`や、`JSON.parse(JSON.stringify())`を使うことでディープコピーが可能です。

```javascript
const original = { name: 'Alice', address: { city: 'Tokyo' } };

// ディープコピー（structuredCloneを使った例）
const deep = structuredClone(original);

// ディープコピー2（JSONのメソッドを使った昔からの例）
// const deep = JSON.parse(JSON.stringify(original));

// 1階層目の変更
deep.name = 'Bob';
console.log(original.name); // "Alice" （変わらない）

// 2階層目（ネストされたオブジェクト）の変更
deep.address.city = 'Osaka';
console.log(original.address.city); // "Tokyo" （完全に独立しているので元のデータは変わらない！）
```

上記は以下の動きになります。

#### メモリの動き

1.  `original = { name: "Alice", address: { city: "Tokyo" } };`の時、以下の挙動になる。（※シャローコピー時と同じ）
    1.  `{ city: "Tokyo" }` がヒープに保存され、そのアドレス(`0x001`)が保存される。
    2.  `{ name: "Alice", address: 0x001 }`がヒープに保存され、スタック上の`original`にそのアドレス(`0x002`)が保存される。
2.  `deep = structuredClone(original);`とすると、すべての階層で**完全に新しいヒープ領域**が確保される。
    1.  内側のオブジェクト `{ city: "Tokyo" }` のための新しいヒープ領域(`0x003`)が確保される。
    2.  外側のオブジェクト `{ name: "Alice", address: 0x003 }` のための新しいヒープ領域(`0x004`)が確保される。
3.  スタック上の変数 `deep` には、その新しいアドレス(`0x004`)が保存される。

つまり、ディープコピーをすると、ネストの奥底まで辿ってすべての実体データを別のヒープ領域に作り直します。

結果として、コピー先(`0x004`や`0x003`)とコピー元(`0x002`や`0x001`)では**共有しているメモリアドレスが一つもなくなる**ため、どこを変更しても元のデータに一切影響を与えなくなります。

シャローコピー・ディープコピーの違いを忘れがちでしたが、スタックとヒープの挙動をイメージすることでよく理解することができました。
